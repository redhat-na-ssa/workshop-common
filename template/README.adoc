== Layout

[cols="1,2"]
|===
|Path |What it is

|`content/`
|The site's home part: `index.adoc` (Workshop home), `instructor.adoc` (Workshop instructor) and `attendee.adoc` (Workshop attendee), `cli-tools.adoc` (Shared CLI tools), and `antora.yml`, whose title, navigation and attributes the whole site uses.

|`workshops/<name>/`
|One workshop each, with its pages under `modules/<name>/pages` and its order in `modules/<name>/nav.adoc`.

|`tools/install.sh`
|The command-line tools the workshops need beyond the shared ones, for the release's tools image; list them in `extra-cli-tools` in `content/antora.yml` too, for the Shared CLI tools page.
|===

== Working on the Workshops

Every pull request runs *Check content*, which holds the lines it changes to the formatting conventions, checks that the site and each workshop on its own build without warnings or broken links, and *Test PDF Build*.
A merge to `main` publishes the site.

With https://github.com/@@OWNER@@/workshop-common[workshop-common] checked out next to this repo, preview the whole site from this repo's folder:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch
----

Preview one workshop on its own:

[source,bash]
----
../workshop-common/scripts/preview.sh --watch --workshop <name>
----

Each builds the site the way the Pages workflow does, serves it on http://localhost:8080/ and rebuilds it when you save a change.
They need Node.js and Python 3.

Add a workshop:

[source,bash]
----
../workshop-common/scripts/add-workshop.py <name> "<Title>"
----

== Releases

Run the *Release* workflow from the Actions tab with the next version, such as `v1.1.0`, or push a tag of that name.
It publishes the PDF, the runtime and tools images, the Helm chart and an offline bundle for disconnected clusters; see "Releases" in workshop-common's README.
